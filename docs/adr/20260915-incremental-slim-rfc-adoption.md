# 增量采纳外部轻量化评审意见

日期：2026-09-15

## 背景

PR #5（`1a222bb`）引入[轻量化 RFC](../proposals/2026-09-15-lite-harness-slim-down.md)；本地 `bc1c510` 已合并该更新。评审基于旧循环，本地已通过 `e854890` 默认日常协作、通过 `f769597` 移除 current 和单 active 槽。直接执行原 Phase 0–2 会重新引入已移除的状态与额外配置。

## 决策

增量采纳需求、证据与项目角色边界，工作规则统一在根目录 [CLAUDE.md](../../CLAUDE.md) 维护。Spec/AC 定义需求，program 评估规则落实验收判据；冲突或影响实现的未决问题先澄清。smoke、静态检查和探针不能代替约定的 QA 或实机验收。

多角色项目在已有权威文档声明 Spec 路径及 Design、QA、Producer 权限，从架构入口链接；采用该分工后执行批准、QA PASS 与 Done 确认。普通小修不强制增加角色或状态文件。工具就绪或归档不代替项目约定的产品验收；自动循环中的必需人工验收落实为人工步骤，尚未落实的约束先记为 blocker。

保留[日常协作默认](20260909-default-lightweight-collaboration.md)与[直接查询 OpenSpec](20260909-query-openspec-without-current.md)的既有决策。不引入 lite/strict 配置，不恢复 current 或单槽，不放松自动循环的不同 agent/model、提交隔离、七项门槛、人工步骤与归档回滚点。

## 取舍与影响范围

保留外部角色评审原文，并明确历史建议与采纳结论的效力，避免把组织规则误变成所有小任务的强制仪式。改动限于规则、文档及 program 模板说明；CLI、API、JSON schema、脚本和看板运行行为不变。

更新器继续按 manifest 同步脚本、看板和模板说明。采用项目手动合并 CLAUDE、AGENTS 引用及循环 program 规则，保留原有产品事实、角色政策和验收契约；不新增全局状态权威。

## 验证方式与回滚条件

本次按日常协作执行，无对应 OpenSpec change。验证使用文档引用检查、`git diff --check`，并核对普通小修、多角色项目、已有自动循环三个场景；实际结果记录在提交及交付说明，不宣称 Unity 或产品功能已验证。

若采用项目发现角色规则与其既有授权冲突，先澄清并修订项目声明及相关说明；如需修改自动循环门槛或归档机制，另行设计并记录取代本决策的 ADR，不靠回退文档绕过既有验收。
